# Santra migration handoff

Branch: `feat/video-audio-workbench`, forked from `d2c`. The video/audio workbench changes are **uncommitted** unless a later commit says otherwise.

Current worktree work: video tools are merged in the capability registry (`crop-resize`, `rotate-flip`, `frames-gif`, `audio-output`), and the video editor uses a stacked full-width preview with event-driven transport. Split and redaction are multi-track; redaction supports rectangle/circle/triangle/freehand masks with fill/outline and time-gated compositing. Audio tools open their own popup window (`AudioToolHost.tsx`, `santra-audio-tool=1`) with waveform + native playback, and the workspace keeps only an in-window fallback when the desktop bridge cannot open it. Audio still has no WaveSurfer regions/envelopes/recording and no volume/fade/mute/speed/noise-reduction controls; merge is concatenation, not a mix.

The previous handoff state follows.

Image and remaining-frame follow-ups are committed in `d12ca25`. The new cursor-placement follow-up is **uncommitted**: native ring/unknown card geometry is centered in its host, workspace placement measures the ring against the opening cursor, and native placement uses configured dimensions and target-monitor scaling rather than potentially zero startup dimensions. Screen-edge clamping is preserved, and the wheel stays still while choosing. Frames 01–10 now share white rounded wheel geometry in `common/ReferenceWheel.tsx` and family icons/order in `wheel-profiles.ts`. Supported video/audio, archive and conversion reviews use `ReferenceEditor.tsx` at 800×560; PDF retains its validated dialog with matching layout. Proposal-only office conversion, archive inspection, EPUB certification, and other unimplemented tools remain disabled.

MKV routing is fixed end to end: `file-kind.ts` shares extension/MIME hints; unknown native drags stay neutral. Rust reads bounded signatures on drag-enter without recursing directories, then sends the inspected family to the owning renderer. Per-window generation counters discard stale inspection results. Category checks prevent a recognized signature from exposing a mismatched extension's routes. Tests cover uppercase MKV, generic MIME, an image-to-video drag transition, and selecting a video operation before drop. Native drag events still require manual GNOME/Explorer validation.

Latest validation (native Windows 11, MSVC): `npm run test` passes 18 Rust tests and 5 Windows protocol tests, `npm run typecheck` and `npm run build` pass, and all 44 Chromium tests pass. `npm run desktop` compiles the backend and launches the native Tauri app. The Windows toolchain is now complete: Rust 1.99.1 MSVC on `PATH`, Visual Studio Community 2022 with the `Microsoft.VisualStudio.Component.VC.Tools.x86.x64` component (MSVC 14.44.35207), and Windows SDK 10.0.22621.0. Two fixes were needed to get there. `native/windows/drag_watcher.cpp` reads `..\native\windows\build\santra-drag-watcher.exe`, which `tauri.windows.conf.json` requires as a bundle resource, so `npm run build:windows-hook` must run before any `tauri` build; and the file was missing `#define NOMINMAX` before `#include <windows.h>`, so `windows.h`'s `max`/`min` macros corrupted `std::max` at lines 39, 40, 378 and 379. That omission would break the MinGW cross build too. The stale `split_ranges_are_ordered_and_bounded` Rust test still asserted the old non-overlap rule; it is now `split_ranges_are_independent_and_bounded` and accepts overlapping, reordered and repeated ranges while still rejecting inverted, negative, non-finite, empty and over-seven-day ranges. The previous Linux `.deb` is at `src-tauri/target/release/bundle/deb/Santra_0.1.0_amd64.deb`; use `apt install --reinstall` because the version remains 0.1.0. No Windows NSIS package or real native file-manager drag is newly certified. Browser screenshot coverage includes every family/mode and supported media editors. The 39 KB WebM fixture under `tests/fixtures/` is used only for playable browser preview tests.

GNOME's legacy `santara-wheel@santara.local` command-template on this machine was previously corrected from `/usr/bin/santara` and old flags to `/usr/bin/santra` with `--santra-*` flags. The prior native X11 wheel smoke required a second show command on cold startup; do not claim cold-start drag validation. Do not commit the cursor-placement follow-up without a new user instruction.

The local job system preserves the source and writes beside it by default; a configured output folder can override that destination.
